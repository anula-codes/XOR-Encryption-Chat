How XOR works — and where it breaks down

01. Input processing

Every character becomes an 8-bit binary number before any math happens.

02. XOR ciphering

Exclusive OR runs between each message bit and the matching key bit, repeating the key as needed.

03. Round-trip check

XOR is its own inverse, so applying the identical key again restores the plaintext exactly.

Why this isn't secure on its own: once a key is shorter than the message, it repeats — and repeating XOR keystreams leak patterns to frequency analysis, the same weakness that broke the Vigenère cipher centuries ago. There's also no authentication, so a flipped ciphertext bit is never detected. Real systems use standards like AES-GCM or ChaCha20-Poly1305, which add both key-stream unpredictability and integrity checks.

All computation happens client-side in this browser tab. Nothing is sent anywhere.
